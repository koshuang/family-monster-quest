# Nightly next-step guardrail

This file intentionally keeps the overnight engineering direction narrow until the first child-facing playtest.

## Principle

Do not add combat, evolution, monetization, or large content systems before the core real-world-task → world-change → exploration → creature-discovery loop is observed with a child.

## Safe-to-build before playtest

- clearer child-world presentation
- stronger event-state cues
- repeatable playtest setup/reset
- deterministic tests
- packaging/export convenience
- parent-side friction reduction that does not alter reward psychology

## Evidence gate

Issue #5 remains the product decision gate. Engineering may continue only on work that improves the quality or repeatability of that test without changing the hypothesis being tested.
